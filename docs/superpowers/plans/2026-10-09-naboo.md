# Naboo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Naboo as the surface engine's showpiece: the foliage design's land and water, Theed with two interiors and a Sith duel, a bongo that dives to Otoh Gunga and runs the planet's core, the battle for the plains behind the Gungan shield, an N-1 to fly, and the run into the droid control ship from orbit.

**Architecture:** The site stays data (`sites/naboo.js`, split out of `sites/core.js` first, with Naboo's builders split out of `props/core.js` behind a barrel). The engine gains small pure additions other worlds can use (a dive ride, a leap, a bank spring, timed solids, a bolt-stopping shield, a shutdown ending, a booma, a ride door, a wet scatter filter, falls sound sources), each tested beside its file; Naboo's content composes them. New people and creatures are built figures now and gen3d asks for later.

**Tech Stack:** three.js 0.186, React 19, Vite 8, Vitest 5 in Node (`npm test`), Playwright-core and Chromium for the browser checks (`scripts/surface-shot.mjs`, `scripts/galaxy-check.mjs`), the site's own `lib/three/foliage.js`, `lib/three/tracks.js`, `lib/combat/bolt.js`, `lib/ai`. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-09-naboo-design.md`. Read with it: `docs/superpowers/specs/2026-10-06-foliage-landscape-design.md` (“Naboo (TPM, AOTC)” and §2.3–2.6 for the species' materials and cards), `docs/health/RULES.md`, `.claude/skills/autopilot/SKILL.md` §5 (the standing rules).

## Global Constraints

- Layers: `src/lib` imports no React and no world; `src/lib/three` knows no world; `src/runtime` imports nothing from `src/components`; a world imports another only through its `index.js` or `shared/` (`docs/health/RULES.md`).
- Every file under 800 lines. `scene.js` (3,571 lines) grows by at most 60 lines net over the whole plan: new behaviour goes in new modules it calls (`underwater.js`, `rideDoor` in `placer.js` or `zones.js`, the probe in `water.js`).
- Pure rules in a tested module beside its test; a test runs under a second, no network, a `rand` argument where chance is needed.
- No new dependency; no runtime asset-service call; `WORLD_MB['/galaxy']` stays 8; `art-mix` stays 7; `big-files` does not rise (the split lowers it by one).
- Budgets at high from Naboo's landing: ≤ 1.6 M triangles, ≤ 360 draw calls (`BUDGET= node scripts/galaxy-check.mjs surface naboo`); each built crown ≤ 1,800 triangles at LOD0, ≤ 400 at LOD1, the gungan tree ≤ 6,000.
- The foliage design's numbers verbatim: grass base `#405138`, mid `#718332`, tip `#8EA33D`; lake `#2c3d3e` / `#172526`; pools `#79A7B0` / `#517C79`; sky zenith `#79A2C9`, horizon `#cfe4ef`, haze `#8CA5B2`; wind 0.5; the species' colours in its Naboo table.
- Copy: British spelling, curly quotes, sentence case, no Oxford comma; a toast is one sentence; prompts key first. No famous line longer than one sentence.
- Comments in the codebase's voice: a prose header per file saying why, with the signatures.
- Commits: one plain sentence about what changed, the body saying why and any numbers, ending with the harness's attribution lines; no model names anywhere in the repo.
- Before each phase's last commit: `npm run lint`, `npm test`, `npm run build`, `node scripts/health.mjs --check --skip build`, all green; the browser checks the phase names.
- All work on the branch `claude/dazzling-gates-54uwrp`; push with `git push -u origin claude/dazzling-gates-54uwrp` after each phase.

## Review Focus

1. A laser gate shutting while the player or the duellist stands in its box: the solid must push them to one side, never trap or hurt them (Task 3.3's test `a gate shutting on someone pushes them out`).
2. The bongo on the surface at the lake's edge where the ground rises above the water: the dive ride must never go under the ground nor be driven up a beach (Task 4.1's test `never under the ground, never over the shore`).
3. The shield's bubble while a defender stands exactly on its boundary firing out: an inside-to-outside bolt passes, an outside-to-inside one stops, and a bolt that starts inside and ends inside passes (Task 5.2's test `a bolt wholly inside passes`).
4. The shutdown on a defenders' win when an attacker is mid-ragdoll already: no soldier is downed twice and the ragdoll cap holds (Task 5.4's test `shutdown downs each standing attacker once`).
5. The probe on a tier that lowers itself mid-session (`lib/three/pace`): the probe is rendered once at build and never again, and under `high` it is not rendered at all (Task 2.5's test `probe wanted only at high and ultra`).
