# Dimension C-137 World Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/c-137` opens on a walkable, flyable, cel-shaded 3D Rick and Morty neighbourhood (Smith house, garage lab, Harry Herpson High; a portal to an alien street with Blips and Chitz) with Roy: A Life Well Lived playable in the arcade.

**Architecture:** Same split as the site's other worlds (Albuquerque, the Shire): pure, tested `rules.js` modules decide everything; `scene.js` modules only draw what they're handed; a React component drives the loop, HUD and overlays. Interiors and the alien street are separate areas far off in the same scene, switched by the component.

**Tech Stack:** React 18, Vite 5, three.js 0.180 (GLTFLoader + MeshoptDecoder, MeshToonMaterial, `portal/toon.js`'s `InkPass`), Vitest, Meshy API (offline, via `scripts/meshy.mjs`).

**Spec:** `docs/superpowers/specs/2026-10-05-c137-world-design.md`

## Global Constraints

- Metres; +x east, +z south. A figure's `face` turns its +x to face `(cos face, -sin face)` (the Shire/towns convention; `face = π/2` faces north, -z).
- Pure rules modules import no three.js and no DOM; scene modules decide nothing.
- Use the existing helpers, don't copy them: `towns/walker.js` (`makeWalker`, `pushOut`, `cameraMove`, `behindYaw`), `towns/keys.js` (`keyDown`, `keyUp`), `portal/toon.js` (`toon`, `toonify`, `InkPass`), `portal/meshyCast.js` (`createMeshyCast`), `lib/stage3d.js` (`canvasTexture`, `disposeTree`), `lib/three/renderer.js` (`createRenderer`, `precompile`, `releaseContext`), `lib/device.js` (`budget`, `pixelRatio`), `lib/three/pace.js` (`createPace`), `lib/hooks.js` (`local`, `useFrameLoop`, `useInView`, `useMediaQuery`), `games/pad.js` (`readPad`, `typing`), `lib/gpu.js` (`use3D`).
- Every Meshy model has a code-drawn stand-in; a model failing to load never breaks the world.
- Copy: the site's voice (plain British-leaning English, sentence case, no exclamation-heavy hype). No quoted show dialogue beyond "I'm not ready to die" and the Meeseeks/catchphrases the page already uses.
- localStorage keys start `tp-c137-`. Achievements: `roy`, `royfiftyfive`, `offthegrid`, `goldstar`.
- No new npm dependencies.
- Code style: match the repo (2-space, single quotes, prettier width ~200, top-of-file comment saying what the module is, comments sparse and plain).
- Implementers do not commit; the controller commits after review.

## Review Focus

1. Keys held when an overlay opens or the tab blurs must not leave Morty walking (clear held keys on overlay open, blur and area change) — test `stepMorty` with zero input after a held run stops within 0.5 s; component clears `held` on those events.
2. Landing the cruiser on a roof or inside a building footprint must be refused, and Morty must never be placed inside a collider when he gets out — test `canLand` false over every building, and `exitCruiser` returns a point `pushOut` leaves unchanged.
3. Going through a door/portal and straight back must not ping-pong (arrival point is outside the link's trigger radius) — test every link's `arrive` is farther than its target link's `r` from that link.
4. Roy's finale must always end (age cap 100) and a failed cancer stage must end at 45 — tests in Task 3.
5. Leaving the page mid-Roy or mid-flight must dispose the renderer and keep progress — component cleanup disposes both scenes; progress written on every task completion, not on unmount only.
