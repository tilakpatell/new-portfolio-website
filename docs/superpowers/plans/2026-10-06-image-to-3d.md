# Local image-to-3D pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the site's 3D models on this machine's RTX 5090, concept image → 3D → web GLB, at a quality that beats the Meshy models the site has, judged on renders of the same subject.

**Architecture:** `scripts/gen3d/` holds the pipeline. `picture.mjs` makes a clean orthographic concept image from a prompt (stable-diffusion.cpp + Z-Image-Turbo, local). `generate.mjs` turns an image into a raw textured GLB through one of two engines behind one interface: `trellis.cpp` (Windows, CUDA, f16 GGUF) or the reference `TRELLIS.2` (WSL, bf16, all CUDA extensions); `--engine` picks, `--bakeoff` runs both on the same images. `web.mjs` makes the raw GLB web-ready with the same gltf-transform steps `scripts/meshy-import.mjs` uses (weld, simplify to a triangle budget, WebP textures at a set size, meshopt) and credits it in `public/games/credits.json`. `judge.mjs` renders any GLB from four views (headless Edge via `scripts/glb-shot.mjs`) for side-by-side pictures; quality is decided by looking, with triangle count, texture size and file size alongside.

**Tech Stack:** Node (gltf-transform, meshoptimizer, sharp, playwright-core driving Edge), trellis.cpp v0.8.1 (CUDA build), microsoft/TRELLIS.2 (bf16; conda CUDA 12.8 toolkit, torch 2.8 cu128, flash-attn, nvdiffrast, nvdiffrec, CuMesh, FlexGEMM, o-voxel in WSL Ubuntu-24.04), stable-diffusion.cpp (CUDA) + Z-Image-Turbo GGUF.

**Spec:** the user's brief in this session: concept image → local 3D latent model → web optimisation, TRELLIS 2 first, Hunyuan3D 2.1 for characters; "the output MUST be good and high quality to use it"; install risk accepted; GPU shared with the voice work; commit regularly, PR, merge to main.

## Global Constraints

- Quality is judged on renders, side by side with the Meshy model of the same subject, before any new model replaces one on the site.
- Web budget as `meshy-import.mjs`: 8k–24k triangles, 512–1024 px textures, meshopt; GLBs load through `src/lib/three/gltf.js`.
- Generated raw outputs, weights, and concept images stay out of git (scripts/gen3d/cache/, git-ignored); only web GLBs and their concept PNG go in.
- Nothing under scripts/voices/, public/audio/voiced/, src/lib/voiced.js, src/lib/useVoiced.js changes here.
- Check `nvidia-smi` before a GPU job; no 3D generation while a voice run holds the card.

## Review Focus

- A concept image with a busy background: background removal (trellis.cpp has birefnet) must leave only the object, or the mesh grows a floor.
- An image of a thin/hollow object (X-wing engines, a helmet): open surfaces survive both generation and decimation (no sealed blobs).
- Decimation to budget keeps UV seams and PBR textures (base colour, metallic/roughness, normal) intact in the web GLB.
- A GLB over 1 MB or over the triangle budget is refused by `web.mjs`, not silently shipped.
- The engine not installed (WSL build failed): `generate.mjs` says so and uses the other.
